03 / EXPLANATION, TERM & FAILURE MODE

A row stays one row

Each failed rule adds a reason. A row with any reason enters the held set once. Accepted and held rows form a partition: every input row appears in exactly one set. Summing the reason counts does not produce a row count when reasons overlap.

Technical terms: an exception queue preserves records and reasons that need review. Grain is what one row represents. A false positive occurs when a check flags a valid case under the intended contract—for example, rejecting every repeated participant in an event table.

Failure mode: “Drop repeated participant labels until there are no duplicates.” Rows 1 and 2 already share P-A but represent different events. That rule would erase an allowed event. A repeated event ID is a different problem and needs investigation.

Isomo connection

Before a synthetic weekly activity report is released, a reviewer needs both the rule evidence and the affected rows. A passing subset does not prove a complete report. A flag begins investigation; it does not grant authority to rewrite the source or decide who someone is.

Static worked example · usable without JavaScript

Four event rows initially pass. Row 3 then loses its participant label and receives −5 minutes. Required-label and minutes rules both fail on that one row: 2 reasons, 1 held row, 3 accepted rows. Reconciliation is 4 = 3 + 1.

If row 2 also takes row 1's event ID, both rows 1 and 2 fail the repeated-event rule. Now there are 4 failed row–rule checks on 3 held rows, with 1 accepted. Reconciliation is 4 = 1 + 3. Repeated participant P-A alone would not fail.

Draw one box per event and put each rule's label inside its affected boxes. Count labels, then boxes. Explain why those totals differ. A passing rule set still cannot establish source truth or population coverage.
