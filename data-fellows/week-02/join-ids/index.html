The technical names

Key
The column used to decide which rows belong together. A stable identifier is meant to stay attached to the same learner across files and over time. A display name is not a key: two learners can share one, and one learner can be typed several ways.
Cardinality
How many rows on one side can match a row on the other. One learner to many events (one-to-many) is expected. A roster key that appears twice breaks the roster's grain and multiplies every match.
Left, inner, right join
Which side keeps its unmatched rows. The join type decides who silently disappears from your output.
Unmatched rows
Rows on either side with no partner. They are evidence to reconcile, not noise to drop.

Failure modes

A duplicated roster key inflates totals. A name-based match attaches one learner's events to another. An inner join hides learners with no activity and activity with no learner. Each output can look tidy. Count and inspect all three before you use a total.

Isomo application

An Isomo report may need to match a platform export to a learner roster. The owner must confirm which identifier can link the records. When you join an export to the learner master, state the grain of each side, the key, the relationship you expect, and what you will do with unmatched or blank IDs before an agent writes the join. Never resolve a real identity by guessing, and never paste real learner rows into a prompt to “see what matches”.

Transfer question

Baseline and endline test files are each meant to have one row per learner. After joining them on learner ID you get more rows than learners in either file. 1 Left join on ID: A matches E1 and E2 (2 rows), B matches E3 (1), C matches nothing but is kept with a blank side (1) = 4 rows. E4 has no roster learner and is left out; output minutes 45, not 50.

2 Inner join: only matches: 3 rows. C and E4 both disappear.

3 B listed twice, left join: each B row matches E3, so E3 appears twice: 5 rows, and minutes rise to 55 although nothing new happened.

4 Match on display name: A and B share “Aline U.”, so each matches E1, E2 and E3: 3 + 3 + 1 (C) = 7 rows. The totals for A and B now include each other's events.
